# 体感物理模型与踩坑记录

本文解释「倾斜手机 → 钢球滚动」这条链路的每一个环节，以及为什么最终选了现在这套极简结构。
如果你打算改手感，先读这篇——**多数「手感不对」是坐标系或零点问题，不是数值问题**。

## 1. 目标

复刻经典 HTC Teeter 的手感：手机就是一块迷宫盘，球是被重力拉动的钢珠。
倾斜多少度就受多少力，方向就是球滚的方向，没有隐形的加速曲线。

## 2. 传感器数据来源

| 环境 | 来源 | 采样 |
|---|---|---|
| 安卓 APK | 原生 `SensorManager` + `TYPE_ACCELEROMETER`，经 `JavascriptInterface` 供 JS 每帧拉取 | `SENSOR_DELAY_FASTEST` |
| 桌面/移动浏览器 | `DeviceOrientationEvent`（`beta` / `gamma`） | 浏览器决定 |
| 无传感器时 | 自动降级为鼠标拖拽 / 方向键 | — |

WebView 的 `deviceorientation` 在安卓上采样率和延迟都不可控，所以 APK 走原生桥。
Java 侧只做一件事：把加速度计三轴**归一化到 1g** 后输出 `gx,gy,gz`。

```java
double n = Math.sqrt(x*x + y*y + z*z);
gx = (float)(x / n);   // 屏幕 x 方向的重力分量
gy = (float)(y / n);   // 屏幕 y 方向
gz = (float)(z / n);
```

> 加速度计测的是**比力**（含反向重力），不是重力向量本身，这直接导致下面第 3 节的符号差异。

## 3. 坐标约定（最容易出错的地方）

统一约定：**右倾为正 → 球向右（+ax）**；**顶部抬起为正 → 球向下（+ay）**。

| 输入 | 设备右倾时 | 换算 |
|---|---|---|
| Android 加速度计 `x` | **负** | `rawG = -gx` ← **必须取反** |
| Android 加速度计 `y` | 顶部抬起为正 | `rawB = gy` |
| `deviceorientation.gamma` | 正 | `rawG = sin(gamma)` |
| `deviceorientation.beta` | 顶部抬起为正 | `rawB = sin(beta)` |

这两条路径的 x 轴符号天生相反。曾经所有验证都在浏览器里做（走 gamma，一切正常），
但 APK 走原生加速度计，结果**真机上左右完全反了**。修法是桥接层取反，并额外提供
「水平方向反转」设置项兜底特殊机型/横握。

换算成 `sin` 之后，读数的物理含义就是**重力在屏幕平面上的分量**（1.0 = 1g ≈ 90°）：

```
倾斜 10° → 0.174 g      倾斜 20° → 0.342 g      倾斜 30° → 0.500 g
```

## 4. 输入管线

```
原生/浏览器读数 → 18ms 低通 → 减去握姿基准 → 死区 → × GRAV_GAME → 加速度
```

```js
var a = 1 - Math.exp(-dt / 0.018);       // 只压噪声，约一帧
sG = lerp(sG, rawG, a);
sB = lerp(sB, rawB, a);

var rg = sG - baseG, rb = sB - baseB;   // 净重力分量
if (invertX) rg = -rg;
if (invertY) rb = -rb;
var mag = Math.hypot(rg, rb);
if (mag < TILT_DZ) { ax = ay = 0; return; }

var acc = mag * GRAV_GAME * (sens / 1.8);   // ← 全部的手感都在这条式子
ax = rg / mag * acc;
ay = rb / mag * acc;
```

**中间没有** `atan2`、正弦饱和、幂曲线、角度积分、突变直通、运行中校准。就是一条直线。

### 握姿基准

- 开场卡（球还没动的约 1.15 秒）平均采样当前握姿；
- `Game.start()` 定稿后**永久冻结**，游戏过程中绝不改零点；
- **左右轴永不学习**（`baseG = 0`，保持纯绝对重力），因为左右是玩家的主控制输入；
- 只在明显竖持 `|avg(gy)| > 0.55` 时补偿 y，避免球一开局就贴底；
- 右下角 ◎ 按钮可手动两轴重新对零——那是用户主动触发，不会自己变。

## 5. 物理步进

固定 120 Hz 步长，`requestAnimationFrame` 渲染时做速度外推插值消除步进感。

```js
ax = Input.ax * tileAccel;  ay = Input.ay * tileAccel;

// 反向制动：球正朝一个方向滚，玩家往反方向拉时加成
if (vx*ax + vy*ay < -0.05) { ax *= 1.6; ay *= 1.6; damp *= 1.8; }

vx += ax * dt;  vy += ay * dt;
vx *= Math.exp(-damp * dt);                    // 速度阻尼
vx -= Math.sign(vx) * roll * dt;               // 滚动摩擦（库仑）
if (speed > 0 && speed < 0.4 && |a| < 0.4) v *= 0.80;   // 低速收敛，停得干净
x += vx * dt;   y += vy * dt;
collide();
```

### 墙面碰撞

按撞击强度分流，这是消除「吸附感」的关键：

- **真撞击**（法向冲击 > 0.45）：反弹 + **一次性**切向摩擦 `WFRIC`
- **贴墙微接触**：只清零法向速度，**切向速度原样保留**

早期实现是只要 `vn < 0` 就乘一次 `0.85` 切向摩擦，而球贴墙时每帧都触发碰撞，
`0.85^60 ≈ 0` —— 沿墙滑行瞬间被磨光，看起来就像墙把球吸住了。

## 6. 参数表

| 常量 | 值 | 含义 |
|---|---|---|
| `GRAV_GAME` | 26 | 1g 对应的游戏加速度（格/s²）。**想整体更猛就改这个** |
| `TILT_DZ` | 0.004 | 死区约 0.23°，只滤静止噪声 |
| `VMAX_BASE` | 9 | 基础速度上限，被「球速」设置缩放 |
| `ACC_BASE` | 11 | 拖拽/键盘模式的基础加速度 |
| `DAMP.floor` | 0.28 | 普通地面速度阻尼 |
| `ROLL.floor` | 0.06 | 普通地面滚动摩擦 |
| `REST` | 0.20 | 墙面弹性 |
| `WFRIC` | 0.05 | 墙面切向摩擦 |
| 输入低通 | 18 ms | 噪声抑制 |
| 反向制动 | ×1.6 / 阻尼×1.8 | 顺向完全不介入 |
| 低速收敛 | ×0.80 | 仅 `speed<0.4` 且已回正时 |

都在 `web/engine1.js` 顶部，改完重新跑 `python tools/assemble.py` 即可生效。

## 7. 为什么不用陀螺仪

查过 Teeter 的开源复刻，它**只用加速度计**。我们曾经加过
「陀螺仪角速度积分 + 加速度计 0.6 秒观测校正」的互补滤波，结果更糟：

- 真机陀螺仪有噪声，积分会漂移；
- 姿态剧变时需要重对零，两套参考系互相拉扯，球发抖、迟滞；
- 多一层滤波就多一层延迟，与「一倾斜就动」的目标相悖。

现在 Java 侧只注册 `TYPE_ACCELEROMETER`，JS 侧没有任何角度积分代码。

## 8. 一个绕不开的物理事实

**手机竖着拿时，左右倾斜本质是绕重力轴转动，重力在屏幕平面的投影不变。**
所以任何基于重力投影的控球方案，在竖直姿态下左右方向都会失灵——这不是 bug，是物理。

因此：

- 引导玩家**平放端在手里**玩；
- 竖持时对 y 做静态补偿，避免球贴底；
- 界面提示「倾斜手机即可控球 · 放平一些前后方向会更灵敏」；
- 设置页提供**水平仪气泡**显示净重力分量，用户可一眼判断传感器是否在工作。

另外，加速度→速度→位移是物理必然，第一帧就有速度但位移要 2–3 帧才肉眼可见，
这部分感知延迟只能靠提高增益压缩，无法消除。

## 9. 踩过的坑（按时间顺序）

| 症状 | 根因 | 修法 |
|---|---|---|
| 竖直握机时前后方向完全失灵 | 用 `atan2(y, hypot(x,z))` 算角度，接近 90° 时饱和 | 放弃角度，直接用归一化重力分量 |
| 8° 和 30° 倾斜差别被抹平 | 把倾斜归一化到满力再套 `t^0.85` 曲线 | 改成 `acc = 分量 × GRAV_GAME` 线性 |
| 怎么倾斜球都快不起来 | `DAMP=2.8` 把加速度抵消，稳态速度只有 2 格/s | 阻尼降到 0.28，摩擦降到 0.06 |
| 球自己乱冲、迟滞 | 每关 `Game.start()` 强制 `calibrate()` 把瞬时握姿当水平面；外加陀螺仪融合漂移 | 删掉运行中校准与融合，改为开场学习一次后冻结 |
| 左倾球却向右滚 | Android 加速度计 x 与 `deviceorientation.gamma` 符号相反，浏览器测试掩盖了 | 桥接层 `rawG = -gx`，加反转开关 |
| 左右明显停滞 | 握姿学习把开局已有的倾斜吃掉（实测 `baseG=-0.5`） | 左右轴永不学习 |
| 墙把球吸住 | 切向摩擦每帧应用 | 按撞击强度分流，微接触保留切向速度 |
| 球停不干净、低速 creeping | 降低摩擦后残速收敛太慢 | 低速且回正时按 0.8 收敛 |

**教训**：连续几轮调增益/阻尼都无效时，先检查零点是否在运行中被改动、
以及是否混用了两套姿态参考系。

## 10. 怎么验证改动

别用「设一个固定倾斜值看球动没动」——它测不出连续手感的跳变。推荐：

1. **浏览器连续倾斜**：逐帧注入 0°→30°→0°→-15°→0°，记录 `Input.ax`，
   检查是否单调、有无相邻帧跳变。
2. **模拟器连续注入**：`adb emu sensor set acceleration <x>:<y>:<z>` 逐帧写入渐变值，
   录制 1000+ 帧轨迹，检查加速度连续性、位置有无瞬移。
3. **定量指标**：倾斜 15° 半秒的位移、反向换向耗时、贴墙滑行 60 帧的速度保留率、
   回正后的滑行距离与静止漂移。

当前基线：15° 倾斜 300 ms 球速约 2 格/秒；反向换向约 150 ms；
贴墙滑行保留 65–72% 速度（自由滑行 78%）；平放静止 3 秒零漂移。
